# Analysmall v11 — Fas 1: Kärnan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a deployable v11 core that stores versioned analysis objects, enforces human-only approval, records editorial decisions, and creates a verifiable immutable snapshot chain.

**Architecture:** Keep v11 isolated under `src/lib/v11`; legacy public analysis pages and `src/types/analysis.ts` remain untouched. Pure Zod/domain services validate and construct immutable revisions before the Prisma repository persists them. Snapshot creation loads only approved, non-conflicting data, includes both schema and analysis-model versions plus a parent pointer, canonicalizes the payload with RFC 8785, hashes it with SHA-256, and writes it once.

**Tech Stack:** TypeScript 5.8, Zod 4, Prisma 6/PostgreSQL, Node built-in test runner, Node `crypto`.

## Global Constraints

- This plan implements only Stage 1 (Core); it does not add KPI, thesis, financial-model, valuation, document-extraction, AI, classifier, UI, publishing or `AnalysisHealth` behavior.
- Create an isolated worktree from `main` before execution; do not modify the user's existing dirty files, including `server.ts`.
- Persist `schemaVersion: '11.0'` and semantic `analysisModelVersion: '11.0.0'` in every snapshot payload and database row.
- Percentages are decimal values: `0.20` means 20 percent; unit and currency are separate fields.
- AI and system actors may create proposed objects, but only the sole editor may approve an object, create a `DecisionRecord`, or create a snapshot.
- Approved revisions and snapshots are append-only. No repository method may update or delete their payloads.
- Every snapshot is RFC 8785 canonical JSON and SHA-256 hashed; only approved objects and non-conflicting sources may enter it.
- A root snapshot has `parentSnapshotId: null`; every later snapshot references the latest snapshot for the same base analysis.
- DCF, WACC, terminal value, recommendation activation and target-price activation are out of scope for this phase.
- Existing public analysis data and pages must remain backward-compatible.

- `src/lib/v11/schemas.ts` — Zod contracts for audit metadata, source/fact/assumption/estimate revisions, approval actors, decisions and snapshot metadata.

```ts
export function approveRevision<T extends RevisionLike>(
  input: ApprovalInput<T>, lookup: DependencyLookup,
): T {
  if (input.actor.actorType !== 'editor') throw new RevisionDomainError('HUMAN_APPROVAL_REQUIRED');
  for (const id of input.revision.metadata.dependencyIds) {
    if (lookup(id)?.metadata.approvalStatus !== 'approved') {
      throw new RevisionDomainError('DEPENDENCY_NOT_APPROVED');
    }
  }
  return { ...input.revision, metadata: approvedMetadata(input.revision.metadata, input) };
}
```

Generate a new UUID revision ID, increment revision number, populate editor/time/reason and supersedes revision ID. Never mutate the input. Reject `system` as well as `ai` actors.

export function createDecisionRecord(input: CreateDecisionRecordInput): DecisionRecord {

## Phase 1 Acceptance Criteria

1. A source, reported fact, assumption or estimate is stored as an immutable revision with audit metadata and explicit dependencies.
2. An AI or system actor cannot approve a revision, create a decision record or create a snapshot.
3. An editor approval creates a new revision and fails if any dependency lacks approval.
4. Each decision-bearing revision can have immutable decision history with a reason and evidence IDs.
5. A snapshot contains only approved objects and non-conflicting sources, carries `schemaVersion: '11.0'` and `analysisModelVersion: '11.0.0'`, has a SHA-256 hash of RFC 8785 canonical JSON, and can be verified after persistence.
6. The second snapshot of an analysis links to its first snapshot; snapshots from other analyses cannot be used as parents.
7. No public UI, AI pipeline, valuation method, recommendation, target price or reporting automation is introduced in Phase 1.
